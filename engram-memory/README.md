# @app-apopov/dsh-engram-memory

Память для DSH поверх локального [Engram](https://github.com/Gentleman-Programming/engram): четыре инструмента, которые сами находят проект по рабочей папке сессии и держат общий слой для всех проектов.

## Зачем плагин, если есть MCP

MCP-сервер памяти DSH запускает в каталоге профиля (`~/.dsh/profiles/<profile>`), а не в папке проекта, и не знает, какая папка выбрана в сессии. Поэтому проект приходилось указывать руками в каждом вызове, а забытый вызов сваливал записи в общий бакет.

Плагин берёт проект из `agent.session.header.cwd` — рабочей папки конкретной сессии — и не требует ни инициализации, ни имени проекта в аргументах.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `memory_save` | Сохраняет запись в проект текущей сессии. `scope: "global"` — в общий проект `global`. Типы: `manual`, `decision`, `architecture`, `bugfix`, `pattern`, `config`, `discovery`, `learning`. |
| `memory_search` | Ищет по текущему проекту и по `global` сразу и склеивает выдачу. `all: true` — поиск по всем проектам. |
| `memory_context` | Последние записи текущего проекта и `global` — для восстановления контекста в начале сессии. |
| `memory_delete` | Удаляет записи по `ids` или чистит базу целиком (`all: true`) в текущем проекте или в `global`. По умолчанию мягкое удаление, `hard: true` стирает строки навсегда. Чужие проектные базы инструменту недоступны. |

Память проекта лежит внутри самого проекта — в `<папка>/.dsh-memory/engram.db`. Переименовали или перенесли папку — память переехала вместе с ней, даже на другую машину. Общий слой хранится отдельно, в `~/.engram/engram.db`, и никуда не переезжает.

## Страница плагина

В **Plugins → Memory** (страница бандла) есть таблица памяти: выбор базы (проекты этой машины и общий слой `global`), список записей с типом, областью и датой, кнопки «Изменить» и «Удалить».

- В строке редактирования меняются название и содержание; сохранение идёт через `PATCH /observations/<id>`.
- Удаление спрашивает подтверждение и стирает запись через `DELETE /observations/<id>`.
- Список проектов ведётся в `~/.dsh/engram-memory/projects.json` — это те папки, где память уже использовалась. Новый проект появляется в списке после первой записи или поиска в нём.
- Всё это работает через авторизованный маршрут `/api/engram-memory`; клиентская половина ничего не читает из базы напрямую.

## Установка

```sh
cd ~/.dsh/profiles/desktop
pnpm add link:/Users/ruelephant/dev-project/deepseek/plugins/engram-memory
```

Затем имя бандла добавляется в `dsh.profile.bundles` в `package.json` профиля:

```json
"@app-apopov/dsh-engram-memory"
```

Плагин подхватывается без перезапуска, когда DSH перечитывает состав профиля.

## Требования

- Установленный `engram` (`brew install gentleman-programming/tap/engram` или `go install github.com/Gentleman-Programming/engram/cmd/engram@v1.20.0`).
- Общая база — `~/.engram/engram.db`, база проекта — `<папка>/.dsh-memory/engram.db`.

## Конфигурация

Поля необязательные; по умолчанию команда ищется в `ENGRAM_BIN`, затем в `~/go/bin/engram`, затем в `PATH`.

```yaml
- id: engram-memory
  name: '@app-apopov/dsh-engram-memory'
  config:
    command: /Users/ruelephant/go/bin/engram
    port: 7437
```

## Как работает

- При загрузке плагин проверяет `GET /health` на `127.0.0.1:7437`; если сервиса нет — запускает `engram serve <port>` и ждёт готовности до 10 секунд. Уже запущенный сервис переиспользуется и не останавливается.
- Для каждого проекта, в котором идёт работа, поднимается свой локальный Engram с `ENGRAM_DATA_DIR=<папка>/.dsh-memory`; порт выбирается из диапазона 7440–7499, сервис поднимается при первом обращении и живёт до выхода приложения. Внутри проектной базы проект называется `local`, потому что идентичность — это сама папка.
- Каталог `.dsh-memory` создаётся сам и содержит `.gitignore` с `*`, поэтому не попадает в `git status`.
- Двенадцать последних записей общего проекта кэшируются и попадают в системный промпт блоком «Shared global memory»: глобальные правила действуют в первой же реплике новой сессии, без вызова инструментов. Кэш обновляется после каждой глобальной записи и по истечении 30 секунд.
- Для каждой пары «сессия DSH + проект» создаётся сессия Engram (`POST /sessions` с `project` и `directory`); id сессии включает проект, потому что Engram отвергает запись, чей проект не совпадает с проектом сессии.
- `memory_search` и `memory_context` опрашивают обе базы — проектную и общую — и склеивают результат без дублей; поиск упорядочен по релевантности FTS5, контекст — по времени.

## Ограничения

- Память проекта живёт в его папке: удалили папку — удалилась память проекта; скопировали папку — у копии своя независимая память. Общий слой (`scope: "global"`) при этом остаётся в `~/.engram`.
- `engram` должен быть установлен: плагин ищет его в `ENGRAM_BIN`, затем `~/go/bin/engram`, затем `PATH`.
- Сквозного поиска в Engram нет: `scope` у записи не расширяет выдачу, поэтому общий слой и живёт отдельным проектом `global`, а склейку делает плагин.
- Инструменты не поддерживают `mem_judge`, timeline и сессии Engram — это остаётся в CLI и в MCP-сервере. MCP-строка в `~/.dsh/cordis.patch.yml` сохранена как `disabled: true`; чтобы вернуть `mcp__engram__*`, поставьте `disabled: false`.

## Проверка

1. Скажите модели «запомни, что проверка памяти — лапсанг», дождитесь `memory_save`.
2. Начните новую сессию в той же папке и спросите про проверку памяти — модель должна вызвать `memory_search` и найти запись.
3. Повторите в другой папке: запись не должна находиться, пока не передан `all: true`.

Из терминала: `engram tui`, `engram projects list`, `engram search "слово" --project core`.
