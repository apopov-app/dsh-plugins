# Действия с изображением

Плагин для DSH: на полноэкранном просмотре картинки появляется меню действий.
Раньше по клику на изображение в диалоге открывался только просмотр — закрыть
и всё; теперь прямо из него можно скопировать картинку, сохранить файл,
показать его в Finder и скопировать путь или ссылку.

## Что добавляется

Рядом с кнопкой закрытия просмотра появляется кнопка «⋯». Она же открывается
правым кликом по картинке или по затемнённому фону. В меню:

| Пункт | Что делает |
|---|---|
| **Копировать изображение** | Кладёт саму картинку в системный буфер обмена (PNG). Работает и для вложений, и для локальных файлов, и для удалённых картинок. |
| **Сохранить в «Загрузки»** | Сохраняет файл в `~/Downloads/DSH Images` под читаемым именем. В уведомлении есть кнопка «Показать». |
| **Показать в Finder** | Открывает Finder с выделенным файлом. Для картинки из файла проекта — оригинал; для вложения — сохранённая копия. |
| **Скопировать путь** / **Скопировать ссылку** | Копирует путь к оригиналу или сохранённой копии, а для удалённой картинки — её URL. |

Горячие клавиши, пока просмотр открыт: **⌘C** — копировать (на Windows и Linux
Ctrl+C), **⌘S** — сохранить. Значения клавиш в меню подставляются по платформе.

Название файла берётся из имени исходного файла, последнего сегмента URL или
alt-текста картинки; расширение определяется по содержимому, а не по подсказке.
Совпадения имён получают суффикс ` (2)`, ` (3)`; ничего не перезаписывается.

## Как это работает

- **Клиентская половина** (`client.js`) не трогает чужой React-компонент
  просмотра. Она находит портал просмотра в `document.body` по структуре
  (`role="dialog"`, `aria-modal`, одна картинка, одна кнопка закрытия, нет
  текста), ставит кнопку действий рядом с крестиком и рисует меню в
  собственном портале поверх просмотра. Правый клик перехватывается до
  обработчика фона, поэтому меню не закрывает просмотр.
- **Хостовая половина** (`index.js`) регистрирует аутентифицированный маршрут
  `/api/image-actions`. Браузер не умеет писать в `Загрузки` и открывать Finder,
  поэтому сохранение и показ файла делает хост:
  - `save` — принять байты из браузера;
  - `save-path` — скопировать локальный файл, на который указывает
    `/api/file?path=…`;
  - `save-src` и `read` — скачать удалённую картинку, когда браузер упёрся в
    CORS (буфер обмена и сохранение работают и для таких картинок);
  - `reveal` — открыть Finder/Проводник с файлом.

  Принять к записи можно только известный формат изображения (PNG, JPEG, GIF,
  WebP, BMP, AVIF, SVG): расширение и содержимое проверяются по сигнатуре.
  Имя очищается от разделителей, управляющих символов и зарезервированных имён
  Windows, а файл создаётся с флагом `wx` — существующий не перезаписывается.

Ничего не уходит в сеть, кроме запроса за удалённой картинкой, которую просмотр
и так показывает. Сохранённые файлы лежат локально.

## Установка

Пакет ещё не опубликован в npm, поэтому ставьте его ссылкой на папку:

```sh
dsh plugin --profile desktop add link:/path/to/dsh-plugins/image-actions
```

После публикации будет доступна обычная установка:

```sh
dsh plugin --profile desktop add @app-apopov/dsh-image-actions
```

После установки перезапустите приложение: хостовая половина регистрирует
маршрут при старте. Клиентская половина подхватывается при загрузке страницы.

Удаление: `dsh plugin --profile desktop remove @app-apopov/dsh-image-actions`.

## Куда сохраняется

`~/Downloads/DSH Images` (на Windows — `%USERPROFILE%\Downloads\DSH Images`).
Каталог можно переопределить переменной `DSH_IMAGE_ACTIONS_DIR`.

## Требования и ограничения

- DeepSeek Harness Desktop **0.2.1-rc.5**. Плагин опирается на разметку
  встроенного полноэкранного просмотра этой версии; после крупного обновления
  клиента её нужно проверить.
- Копирование картинки в буфер требует Chromium-совместимого
  `ClipboardItem` — в приложении для компьютера он есть.
- Картинку в формате, который не распознаётся как изображение (например, HEIC),
  плагин не сохранит и не скопирует: содержимое проверяется по сигнатуре, а не
  по расширению.
- Просмотр, открытый не встроенным компонентом (например, превью в боковой
  панели), меню не получает: плагин реагирует только на полноэкранный просмотр.
